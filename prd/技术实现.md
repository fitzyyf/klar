# 改动星云 · 技术实现

给要做这个工具的人。为什么做、给谁做，见 [产品定位.md](产品定位.md)。界面原型是 [index.html](index.html)，样例数据是 [sample.js](sample.js)。

要解决的事：接上一个 agent 会话，用它自己写下的编辑画出全链。人看完点确定或反馈。工具不执行 `git commit`，也不用 `git diff` 找改动。

## 现在的形态：客户端

单进程桌面客户端，在 [../desktop](../desktop)。不是部署出去的 web 服务：Wails v3 起一个系统网页视图窗口，窗口里就是 `app/ui` 这份 HTML，页面 `fetch` 的 `/api/*` 和页面本身由同一个 `http.Handler` 出（`api.go` 的 `handler`）。窗口双击标题栏放大，顶栏那段自己标出可拖动。

上一版是 Rust + Tauri 2（还带一个 ratatui 的 `klar tui`），已经删干净了，仓库里不再留参照。TUI 这一版没有跟着过来。

## 选型

| 部分 | 选的 | 为什么 |
| --- | --- | --- |
| 语言 | Go 1.26 | 一个二进制；tree-sitter 有官方 go binding |
| 语法解析 | tree-sitter go binding，语法包 java、typescript、javascript、python、go | 一套接口覆盖所有语言；Vue 单文件自己抽出 `<script>` 再按 JS 解 |
| 桌面 | Wails v3（beta） | 系统网页视图，不捆一份浏览器；资源和接口同一个 handler |
| 存储 | SQLite（`modernc.org/sqlite`，纯 Go 不走 cgo），文件在 `~/.klar/reviews.sqlite` | 只记评审结论，图每次现算 |
| 盯文件 | `fsnotify` | 三家会话记录目录一有动静就推页面刷新 |
| 前端 | 原生 HTML，调用链用 ELK 分层加正交走线 | 画的是 UML 活动图的样式：菱形是判定，方框写「循环」，箭头上 `[条件]` 是分支 |

## 进程

```
desktop（一个二进制）
├─ main.go            窗口、拖动、放大
├─ api.go             /api/load /api/session /api/verdict /api/watch，页面也从这里出
└─ internal/
   ├─ history/   三家记录目录里按仓库找已结束的会话
   ├─ sess/      读三家各自的记录格式，切成回合和写文件记录
   ├─ replay/    把编辑叠成每回合开始、结束时的正文
   ├─ lang/      tree-sitter 切函数、抓调用点和分支条件
   ├─ graph/     指到声明、标改动、编全链
   ├─ head/      调用方从参照提交（HEAD）读，不读工作区里没提交的
   ├─ engine/    串起来：列会话、组装一条、记评审
   └─ store/     ~/.klar/reviews.sqlite
```

## 会话名单

不用 seedmux / smx-team 的 pane 名单了，这个工具也不调 `smx-team`。这一版看的是**已经结束**的会话，直接从三家的本地记录目录里按仓库找：

| | 目录 | 定位一条会话 |
| --- | --- | --- |
| Claude | `~/.claude/projects/<路径编码>/<sid>.jsonl` | 目录名是仓库路径每个非字母数字换成 `-` |
| Grok | `~/.grok/sessions/<URL 编码的仓库路径>/<sid>/chat_history.jsonl` | 目录名反解回路径 |
| Codex | `~/.codex/sessions/**/*.jsonl` | 第一行 `session_meta` 的 `cwd` 等于仓库；按修改时间取最新的 400 个文件里找 |

一个仓库最多列 80 条，新的在前。每条会话的解析结果按记录文件的路径、修改时间、大小缓存，记录没变就不重读；缓存最多 160 条，满了清空重来。

## 从会话记录取编辑

| | 一个回合 | 写文件工具 | 改前正文 | 这笔失败了 |
| --- | --- | --- | --- | --- |
| Claude | 一条文字的 `user`（不带 `isMeta`、不是系统塞进来的开头）到下一条 | `Write`、`Edit`、`MultiEdit` | 结果里的 `toolUseResult.originalFile` | 对应 `tool_result` 带 `is_error` |
| Codex | `event_msg` 的 `task_started` 到 `task_complete` / `turn_aborted` | `item_completed` 里 `FileChange` 的 `changes`：`add` / `delete` / `update`（unified diff）/ `move_path` | 没有，靠叠或倒放 | `status` 不是 `completed` |
| Grok | `type` 为 `user` 且带 `prompt_index` 的一条 | assistant 里的 `write`、`search_replace` | 同目录 `rewind_points.jsonl`，按 `prompt_index` 取 `file_snapshots` / `after_snapshots` | 结果文字不是 `has been created` / `successfully` |

三家共同的规则：

- 失败的工具调用不进编辑表，列出来划掉、写原因。
- 路径不在仓库里的不算，绝对路径换成相对仓库的。
- Claude 的 `tool_result` 行也是 `type: user`，不当成新回合。
- 会话用 shell 改的文件不进编辑表；之后同一文件对不上就记 `errors`。

## 改了什么

每笔编辑这样落正文（`replay` 包）：

- `write` / `add`：正文整个换掉；`delete`：文件删掉。
- `replace`：当时的正文里 `old_string` 换 `new_string`（`replace_all` 全换）。对不上记「old_string 找不到」。
- `multi`：`MultiEdit` 按顺序逐条 replace。
- `update`：按 unified diff 的 `@@` 段，空格行加 `-` 行拼成原文，换成空格行加 `+` 行。
- 某笔之前正文不知道的：先从最近一次带 `originalFile` / 快照的笔顺推；推不到就从磁盘当前文件**倒放**回去（`+` 行换回 `-` 行、`add` 退成没有这个文件）。倒放也对不上，这个文件记 `errors`，停在这里不编链。
- Grok 有快照的回合直接用快照，快照优先于叠出来的结果。

没有写过文件的回合也保留（这一版开始），对话流要靠它们；只是不编链。

## 从正文到全链

每个回合拿两份正文：回合开始、回合结束。只解析碰过的路径。会话级「净改」取每个文件第一次改之前、最后一次改成功之后，走同一套。

**切函数（`lang` 包）。** Java 方法/构造函数、TS/JS 函数和方法、Vue `<script>` 里的方法、Python 函数、Go 函数。函数体去掉注释拼起来哈希，只改注释或空白视为没改。调用点按出现顺序记，反射、下标、`apply`/`call`、拼出来的名字不建边，标 `unknownCalls`。

**入口**：Java 的 `*Mapping` 一族、`@Scheduled`、`@KafkaListener`、`@RabbitListener`、`@EventListener`、`@XxlJob`、`@JmsListener`；Go 的 `main`、`ServeHTTP`；Vue 的 `mounted` / `created` / `setup` / `onMounted`。往上找不到本仓库调用方的也算入口。

**叶子**：声明在仓库外的被调方；名字带 `Mapper` / `Repository` / `Dao` / `Repo` 的接口型方法。

**指到声明**：按方法名加调用对象的名字接，同类同文件优先；接不唯一标「指向不确定」。

**分支条件（guard）**：从调用点往外看经过的 if / else / switch / 循环 / 三元，条件文本压成一行，画在离开判定菱形的箭头上，格式 `[条件]`。

**编链（`graph` 包）。** 种子是改动过的方法和改动过的跳；拆掉的跳在回合开始的那张图上找，编出来的是虚线。从种子往上走到入口、往下走到叶子。每个入口最多 20 条，一次最多 24 条，整次搜索超过 1 秒停，剩下的计入 `omitted`。

## 结果

每个会话产出一份（`model.go`），窗口读同一份：

```ts
type Output = {
  repo: string; repos: string[]; projects: {path, claude, codex, grok, latest}[];
  sessions: SessionOut[]; notes: string[];
};

type SessionOut = {
  agent; sid; title; baseline;         // baseline 是绑定时 HEAD，只做参照
  bound: "start" | "late";             // codex 一律 late：改前正文靠倒放
  source;                              // 会话记录文件路径
  assembled: boolean;                  // false 是还没组装，只带标题和文件名
  turns: TurnOut[]; net: TurnOut;      // 新的在前；net 是净改
  review?: { at; verdict; text; ok; current };
};

type TurnOut = {
  id; at; prompt; reply?;
  edits: {tool; path; ok; reason?}[];
  files?: {path; before; after}[];     // 每个文件前后两份全文，详情面板用
  stars: {id; label; kind: "entry"|"fn"|"leaf"|"if"; mark?; unknownCalls?; body?}[];
  calls: {key; from; to; change: "add"|"del"|"edit"|"none"; uncertain?; before?; after?; text?; guard?}[];
  chains: {stars; dashed?; broken?}[];
  omitted; errors: {path; reason}[];
};
```

## 界面

- 左栏会话列表：agent 名和时间（最新回合）、标题、评审标记、写过的文件。点一条才组装调用链。
- 画布右下角一条控件：`纵向 / 横向`、`紧凑 / 宽松`、`− 百分比 ＋`、`适应`、`1:1`。方向和疏密存 `localStorage`，**默认纵向**。键盘：方向键平移，`+` `-` 缩放，`0` 适应，`1` 一比一，`f` 把焦点滚到正中；双击空白=适应，双击方框=聚焦并居中。
- 视口记布局坐标，不记像素。同一份布局按坐标精确还原；换方向、换疏密这种重新排版，就认视口中心那颗星，顺着它所在的那条链重新框一次。点节点、拖分隔条、改窗口都不跳。换回合、换会话才重新起头：缩到 `START_MIN`（24 条链全铺开只有 37%，再小看不清），落在这次改动上。
- 点右栏全链某一条，画布把它挪到正中；点画布上的星或跳，右栏清单自动滚到含它的那一条。排版还没回来就先记下，排完补上。
- 「对话流」工作区：每回合一句你说的、一句它说的，文件贴在下面。
- 右栏三行（第一句 / 最近回复 / 实际计数）、全链清单、写过的文件（失败的划掉）、点中星或跳后的函数体 diff。
- 底部「记下通过 / 记下退回」针对整个会话；退回必须写字。记下之后下面出现一个只读框，是要粘给 agent 的话，旁边一个「复制」。图例挂在图左下角。

## 评审动作

会话已经结束，结论**只记在本机** `~/.klar/reviews.sqlite`（repo、sid、at、verdict、text、ok、turn_id）。这个工具不跑 `smx-team`、不跑 tmux、不碰任何 agent 进程，所以它不投递。

点「记下通过 / 记下退回」时，引擎把要交回的那句话拼好，连同结论一起返回给界面，界面放进一个只读框，旁边一个「复制」按钮。**由人自己粘给 agent。** 话里带参照提交和提交说明，粘过去 agent 才知道自己该提交什么：

```
评审通过。请在这个会话里提交。参照 <baseline>。提交说明：<会话标题>。只提交这个会话写过的文件。
评审没通过：<意见>。参照 <baseline>。改完后停下，等下一次评审。
```

`turn_id` 记的是点按钮时最新的回合。之后又出现新回合，`current` 变 false，界面写「上次记了通过，之后又有新回合」，可以再点一次。

界面上不许出现「已发给」「已交给这个会话」。记下了就是记下了，投递没发生就不能写成投递成功。

## 刷新

`fsnotify` 盯三家记录目录（含新建的子目录），200 毫秒内的一串动静并成一次，经 `/api/watch`（SSE）推页面重新拉 `/api/load`。页面在 http 协议下才挂 EventSource。
